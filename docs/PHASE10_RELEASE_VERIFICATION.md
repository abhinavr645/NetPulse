# Phase 10 — release preparation and verification

Verified on Windows 11 x64 with Temurin JDK **25.0.5+8-LTS**, Maven **3.10.1**
and Windows PowerShell. Version: **NetPulse 1.0.0**.

## Release status and exact launch instructions

The self-contained Windows application is runnable through the supplied
**`NetPulse.cmd`**. The actual batch launcher, packaged JAR and bundled runtime
have been launched and tested on Windows. No installed Java/Maven is needed
by this launch route.

1. Extract `NetPulse-1.0.0-windows-x64.zip` completely.
2. Open `NetPulse-1.0.0-windows-x64/NetPulse`.
3. Double-click **NetPulse.cmd**. Keep `app` and `runtime` beside it.
4. Select an adapter and Start Monitoring. For TCP tests, click Start local
   server, then choose Upload/Download and Start Test.
5. Close the main window normally to flush history and stop owned background work.

The native **`NetPulse.exe`** is also generated by `jpackage` with the project
icon. **Windows Application Control blocked this unsigned EXE before Java
started. Its native launch is not claimed as verified.** The read-only Code
Integrity event identified a signing-level/policy failure; the generated EXE
has no Authenticode signer. The bundled `javaw.exe` has a valid Eclipse
Foundation signature. No security policy, trust store or certificate setting
was changed. The supported tested route invokes that bundled runtime with the
application JAR through the batch launcher. A signed custom native launcher
would require an appropriate signing certificate and another verification run.

This release is a **portable Windows x64 application image**, not an MSI/setup
installer. It makes no registry/start-menu changes and includes no uninstaller.

## Packaging method and contents

`packaging/Build-WindowsRelease.ps1` runs the `windows-release` Maven profile,
copies only the application/runtime dependency JARs, calls Java 25 `jpackage
--type app-image`, includes an original pulse icon, copies submission documents
and preserves dependency/runtime legal files. It then builds a ZIP and SHA-256
sidecar. No application dependency was added. The two new Maven plugins are
build tools for the JAR manifest and copying runtime dependencies.

The linked runtime contains `java.base`, `java.datatransfer`, `java.xml`,
`java.prefs`, `java.desktop`, `java.instrument`, `java.logging`,
`java.transaction.xa`, `java.sql` and `jdk.crypto.ec`. `java.instrument` supports
the external acceptance check; the agent is not shipped or enabled for users.
The standard vendor-signed Java launchers are retained for the portable launch
route. The JDK compiler, Maven, JUnit and source/debug distributions are excluded.

```text
release/
  NetPulse-1.0.0-windows-x64.zip
```

Application image size: **95,071,470 bytes (90.67 MiB)**. The complete submission
folder is approximately **95.5 MB**, and its ZIP is approximately **41.5 MB**;
document/screenshot updates can change those last two values slightly. Exact
archive size is reported by the build script, and the final checksum is in the
sidecar outside the ZIP. There is no installer file or installer size to report.

Generated releases are ignored by Git. The build checks for accidental database,
log, PDB, JUnit and test-JAR inclusion. No test database, agent, test report,
Maven cache, personal profile or debug file is part of the release.

## Database and server lifecycle

`DesktopLauncher` selects GUI mode by default and marks packaged data mode.
`DatabaseManager` resolves `%LOCALAPPDATA%\NetPulse\netpulse.db`; missing
LOCALAPPDATA falls back to the user's `AppData/Local/NetPulse`. The explicit
test/developer override takes precedence. Developer `Main` commands preserve
`data/netpulse.db` and their existing argument behavior. No database is bundled
or migrated automatically from the developer directory.

The GUI's Start/Stop local server controls call the existing `BandwidthServer`
from background tasks. The server still binds only to 127.0.0.1:5001. Running,
Stopped and bind-error status are displayed. An occupied port does not result
in ownership of or termination of another server. Closing the window stops a
dashboard-owned server; an independently launched CLI server remains separate.
The TCP protocol and monitoring engines were not rewritten.

```powershell
mvn clean compile
mvn test
```

The acceptance script clears JAVA_HOME/JDK_HOME/CLASSPATH and Java/Maven paths
from each child environment, uses `Windows/System32` as its working directory
and sets an isolated writable LOCALAPPDATA under `target/packaged-verification`.
It verifies the actual loaded runtime and packaged JAR, rather than substituting
development classes. A test-only Java agent reads the real Swing controls in
that process and invokes their normal actions. The final ordinary and batch
launches run without this agent. Test evidence stays outside the release.

A separate Windows machine or VM with Java uninstalled was not available.
Environment-isolated bundled-runtime checks are evidence for runtime resolution,
not a claim of complete clean-machine compatibility.

### Actual Windows observations

The final packaged run transferred exactly **10,000,000 bytes** per mode:

| Operation | Elapsed seconds | Throughput |
|---|---:|---:|
| Upload | 0.037719 | 2120.953 Mbps |
| Download | 0.047479 | 1684.955 Mbps |

Throughput was checked against the exact payload bytes and unrounded nanosecond
duration. Localhost rates are not Wi-Fi or Internet capacity measurements.
The owned server was started, stopped, restarted and closed; an occupied-port
attempt produced the expected error while leaving the other socket untouched.

The actual Wi-Fi sample captured for the report showed **0.089760 Mbps receive**
and **0.013080 Mbps send**. An HTTPS fetch of a public Java reference page
generated real traffic. Both graphs collected successive valid readings and
froze on Stop. Tiny explicitly configured 0.000001 Mbps thresholds produced
actual CRITICAL alerts; production defaults remain disabled / 100 / 50 Mbps.

SQLite contained **2 network readings, 2 alerts**, and observed daily totals
of **43,466 received / 6,995 sent bytes**. These totals matched the monitor's
final session totals. The history viewer showed all three tabs. Restarting the
packaged application restored enabled=true, the thresholds, saved alerts and
history. Closing with a monitor and owned server active stopped the workers and
released port 5001. The image directory was unchanged.

The final source desktop suite separately verified live cards/graphs, resizing,
unavailable adapters, clear-history cancellation/confirmation, storage errors,
lock recovery, a separate TCP server process, large-history limits/time filters,
EDT responsiveness and shutdown during active work. The real adapter did not
become idle in its brief live inactivity check; deterministic tests cover INFO
inactivity detection without inserting fake live readings.

### Failures found during release preparation

- Native EXE launch was blocked by signing policy; this remains a documented
  limitation. No policy was disabled or trusted signing identity fabricated.
- An older desktop test used native mouse/Enter timing for alert deletion and
  failed its clear assertion. It now invokes the same Swing button action,
  explicitly finds the real nested confirmation pane, confirms it and retains
  the history-cleared assertion. Its focused run and the entire seven-case
  rerun passed. An initial test-helper assumption about the dialog's root
  component was corrected; no application behavior/assertion was removed.
- Verification-script issues involving Windows PowerShell syntax,
  case-insensitive variable naming and external-child exit-code handles were
  corrected. The ordinary child now retains a handle until exit is measured.
- Documentation section captures initially scrolled back to the previous focus
  owner and were clipped. The helper clears focus before scrolling and retains
  a visibility assertion. Final screenshots passed and were visually reviewed;
  clipped attempts are not included in the submission.

## Remaining limitations

- The custom native EXE remains unsigned and blocked on this machine; use the
  verified batch launcher. No installer, signing certificate or automatic update
  mechanism is included.
- A fresh machine without Java installed was not tested. Windows policies may
  also restrict scripts, PowerShell, driver statistics or execution locations;
  permissions were not changed to suppress those restrictions.
- Sampling delay, short localhost-test sensitivity, missing adapter intervals,
  possible storage gaps during errors/forced termination and the 500-row viewer
  limit remain as documented. No LAN configuration, packet-loss/latency test,
  cloud service or external alert notification was added.
- Developer and packaged databases are separate; no automatic migration occurs.
  Retention is opt-in; alerts and daily totals are not automatically deleted.
- Complete the student/college/guide placeholders and choose an application
  source license if publishing outside the academic submission context.
